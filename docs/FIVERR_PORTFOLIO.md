## Gig title

**I will build an AI invoice extraction app with OCR review and Excel, CSV and PDF exports**

Alternative: **I will automate PDF invoice data entry with a private FastAPI and React web app**

## Description

I built **InvoiceOps AI**, a local-first web app that turns a batch of PDF invoices into clean, reviewable data and client-ready deliverables.

The workflow is: create a job for an order, upload PDFs or a ZIP, let the extraction engine read native text and OCR scanned pages, review each invoice side-by-side with its source PDF, then generate an Excel workbook, invoices CSV, line-items CSV and a PDF processing report.

It is designed for paid invoice-processing work where accuracy and auditability matter: one job per client, no mixed documents, original values preserved, every manual correction logged, money handled with exact decimals, and totals never mixed across currencies.

## What is included

- FastAPI backend with REST API, SQLAlchemy models and Alembic migrations
- React + TypeScript interface with live progress, filters, review workspace and export center
- Extraction pipeline: PDF inspection, native text, local PaddleOCR PP-OCRv6 Medium fallback, rule-based parsing, validation and SHA-256 duplicate detection
- Optional AI enrichment via local Ollama or Groq, with explicit per-job consent and grounded values only
- Four export formats: XLSX (4 sheets), invoices CSV, line-items CSV and PDF report
- Security: localhost binding, optional admin token, per-job file isolation, ZIP path-traversal protection, retention purge and hard delete
- Windows install scripts, `.env.example`, pinned dependencies and full documentation

## Process I follow

1. Confirm the invoice formats, languages and required output columns.
2. Configure the extraction rules and OCR languages; test on a small sample batch.
3. Run the batch, review exceptions and correct only what is genuinely ambiguous.
4. Export the four deliverables and share the report with status counts.
5. Delete the job from the app when the order is complete.

## Scope notes (transparent)

- One PDF is treated as one invoice; multi-page invoices are fine, but several invoices inside one PDF are not split.
- Native text is always tried first; OCR is used only for pages with no usable text.
- Cloud AI is off by default and never enabled for a job without explicit consent.
- The app runs on Windows from `scripts\start.bat`; it is not a hosted SaaS.
- Demo files in the proof pack are sample invoices supplied for this demonstration. No real client documents are included.

## FAQ

**Can you match our Excel template?** Yes - the export layer is isolated in `backend/app/services/exporter.py`, so columns and sheets can be adjusted.

**How are mistakes handled?** Low-confidence fields are flagged, validation warnings are shown, corrections are audited, and the PDF report states exactly how many invoices were reviewed by a human.

**Are our documents sent to an AI provider?** No. The default setup uses rules and OCR only. Local Ollama keeps text on the machine; Groq requires explicit consent per job.
